to_parquet(path: str | Path, *, mode: str = 'long', join: str = 'outer', if_exists: str = 'append', max_rows_per_file: int = 100_000) → None[source]#

Write this result’s feature data as real Apache Parquet file(s).

mode="long" (the default): path is a single file, written in the same long-form shape as to_arrow() (one row per object per feature column).

mode="wide": the traditional, tabular shape – path is a directory (created if missing); one file per feature scope is written into it, Per_Image.parquet plus one Per_<ObjectName>.parquet per object set (CellProfiler’s own ExportToDatabase table-naming convention, matching to_duckdb()/to_sqlite()’s own tables exactly). Each file has image_id (and, for object scopes, object_id) columns plus one real, named column per feature – feature names are the column names, no extra lookup needed.

mode="array": same per-scope files and id columns as "wide", but every feature is packed into a single features column instead of one column each, as one fixed-size list per row (Arrow FixedSizeListArray – the most direct way Parquet/Arrow represents a per-row numeric vector of known length; it round-trips straight into a dense (n_rows, n_features) numpy array with no separate decoding step). Reading a bare feature array back tells you nothing about which feature each position is; the file’s own Parquet schema metadata carries the exact ordered feature name list for that column, read back with read_parquet_feature_names() – no sidecar file to lose or fall out of sync.

mode="joined": a single combined, CytoTable-style wide table – one row per object, every object scope joined together on object_id (join="outer", the default: every object_id seen in any scope, with nulls where a scope has no matching object; join="inner": only object_ids present in every scope), each scope’s feature columns prefixed with that scope’s name (Cells_Intensity_MeanIntensity_DNA, Nuclei_AreaShape_Area, …) to avoid name collisions between scopes, with every Image-scope feature broadcast onto every row with an Image_ prefix. This assumes matching object_id values across scopes identify the same physical object – true whenever one object set was derived from another (as most of this project’s own fixtures are; see spec/compatibility.md), not guaranteed for independently segmented object sets with no declared parent-child relationship (cp_anywhere has no RelateObjects equivalent). Neighbors relationship rows have no natural per-object column and are not included.

path may be a single .parquet file (one write, no pagination beyond Parquet’s own row groups) or a directory, in which case this writes a real Parquet dataset via pyarrow.dataset.write_dataset – max_rows_per_file bounds each fragment file’s row count (Parquet’s own built-in pagination mechanism, not a bespoke chunking scheme; the 100,000-row default is a common balance between per-file overhead and query/memory efficiency). Calling this repeatedly with a directory path – the usual way to build one combined multi-image dataset, since measure() always processes one image at a time – defaults to if_exists="append", adding a new, uniquely-named fragment file each call without touching existing ones; if_exists="replace" deletes the directory first.

to_sqlite(path: str | Path, *, if_exists: str = 'append') → None[source]#

Write/append the same wide Per_Image/Per_<ObjectName> tables as to_duckdb(), but as SQLite STRICT tables – every column has a declared, enforced type (TEXT/INTEGER/REAL) instead of SQLite’s legacy, permissive type affinity. Requires SQLite 3.37+ (STRICT syntax support); raises RuntimeError naming the running SQLite’s version otherwise, rather than failing on the first CREATE TABLE with a confusing syntax error.

if_exists has the same “append” (default, accumulate across images) / “replace” (drop and recreate) meaning as to_duckdb().

src.cp_anywhere.api.measure(images: Mapping[str, object], objects: Mapping[str, object], *, mask: object | None = None, image_id: str = 'Image', families: Sequence[str] | None = None, neighbors_scopes: Sequence[str] | None = None, neighbors_expand: Sequence[str] | None = None, neighbors_full_objects: Mapping[str, object] | None = None, size_shape_calculate_zernikes: bool = True, size_shape_calculate_advanced: bool = False) → MeasurementResult[source]#

Measure 2D or 3D arrays with the selected CellProfiler 4.2.8 settings.

Float64 C-contiguous images are borrowed by Rust. Other numeric images and strided arrays are converted once. Do not mutate inputs during this call.

The original three default families are unchanged. Select families=["object_size_shape"] explicitly for 2D shape measurements. size_shape_calculate_zernikes=True adds 30 Zernike columns to the 25 standard columns; size_shape_calculate_advanced=True adds 53 moment/inertia columns. Shape measurements ignore the image mask and require consecutive object IDs starting at 1. Sparse shape labels and 3D shape requests raise errors, not misaligned or substitute columns.

neighbors_scopes selects which object set(s) MeasureObjectNeighbors runs against itself (CellProfiler’s own Adjacent distance method; cross-object-set and non-“Adjacent” neighbors remain out of scope – see spec/compatibility.md). Defaults to ("Cells",) when the "neighbors" family is selected and neighbors_scopes is omitted, matching this project’s original declared scope exactly, byte-for-byte (every pre-existing fixture, golden comparison, and caller is unaffected). Pass e.g. neighbors_scopes=("Nuclei", "Cells") to compute it for multiple object sets in one call instead – each one independently, with its own feature columns and relationship rows tagged by an "object_name" key, matching how real CellProfiler pipelines invoke MeasureObjectNeighbors once per object set.

neighbors_expand names which of those scopes use CellProfiler’s “Expand until adjacent” distance method instead of the default “Adjacent”: every background pixel of that scope’s own geometry (neighbors_full_objects when supplied, else its own labels) is first assigned to its nearest foreground pixel’s label (a 2D-only Voronoi expansion – raises if the image is 3D), and touching/ relationship-edge detection runs on that fully covered label image; object centers and the closest-object/distance/angle columns still use the original, unexpanded geometry, exactly matching real CellProfiler’s own run(). Each name must be one of the active neighbors scopes. Columns get an _Expanded suffix instead of _Adjacent for every scope named here.

neighbors_full_objects supplies each scope’s diagnostic geometry (CellProfiler’s objects.small_removed_segmented). Both primary and secondary segmentation results expose it as small_removed_labels. The core matches diagnostic IDs to retained IDs by pixel overlap. Diagnostic objects omitted from the kept set can affect counts, touching percentages, distances, and angles, but do not get output rows or relationship edges. Closest-object numbers are recomputed among retained objects, matching CellProfiler. Which excluded objects appear in the diagnostic layer depends on the segmentation module; primary segmentation’s layer already excludes border objects. A scope with no entry here (the default) uses its kept labels.

The simplest entry point for files on disk: cp_anywhere.io.measure_files() accepts TIFF/OME-TIFF, PNG, or saved NumPy array paths (or already-loaded arrays) directly and returns a tidy pandas.DataFrame, instead of requiring images to be pre-converted to NumPy arrays first.

Load images and label arrays directly from common file formats.

This is the simple entry point for users with ordinary microscopy files (TIFF/OME-TIFF, PNG, or saved NumPy arrays) who do not want to pre-convert anything by hand. measure_files wraps cp_anywhere.api.measure() and returns a tidy pandas.DataFrame instead of a MeasurementResult.

cp_anywhere.segment#

Object segmentation includes cp_anywhere.identify_primary_objects(), cp_anywhere.identify_secondary_objects(), and cp_anywhere.identify_tertiary_objects(). The native implementations use the corresponding CellProfiler modules as the compatibility oracle – see segmentation coverage for the declared scope and verification status.

Object segmentation, implemented against CellProfiler 4.2.8’s IdentifyPrimaryObjects module (and the shared Threshold module it uses) as the compatibility oracle.

Declared scope: every global and adaptive threshold operation (Manual, Otsu two/three-class, Li, Robust Background, Sauvola), log transform, threshold smoothing, declumping/watershed (Intensity/Shape/Propagate), hole filling (including nested-object absorption), border exclusion, and size/count filtering – see spec/segmentation-modules.md for the exact settings mapping and the explicit remaining gaps (not silent approximations).

CellProfiler’s own Threshold module hard-bounds manual_threshold and threshold_range to [0, 1] and assumes images have been rescaled to that range (its default Image(..., convert=True) divides integer-dtype pixels by their dtype’s max value; float-dtype pixels are never rescaled). identify_primary_objects reproduces that default behavior automatically (rescale=True) so passing a raw uint8/ uint16 image works exactly like a default CellProfiler pipeline, with no manual conversion needed.

The result chains directly into cp_anywhere.measure():

seg = cp_anywhere.identify_primary_objects(dna_image, threshold="otsu")
result = cp_anywhere.measure({"DNA": dna_image}, {"Cells": seg.labels})

src.cp_anywhere.segment.identify_primary_objects(image: object, *, mask: object | None = None, threshold: str | float | int = 'otsu', rescale: bool = True, threshold_correction_factor: float = 1.0, threshold_range: tuple[float, float] | None = None, exclude_size: bool = False, min_diameter: float = _MIN_DIAMETER_DEFAULT, max_diameter: float = _MAX_DIAMETER_DEFAULT, exclude_border_objects: bool = False, maximum_object_count: int | None = None, fill_holes: str = 'never', threshold_smoothing_scale: float = 0.0, assign_middle_to_foreground: bool = True, robust_background_lower_outlier_fraction: float = 0.05, robust_background_upper_outlier_fraction: float = 0.05, robust_background_averaging_method: str = 'mean', robust_background_variance_method: str = 'sd', robust_background_number_of_deviations: float = 2.0, log_transform: bool = False, threshold_scope: str = 'global', adaptive_window_size: int = 50, unclump_method: str = 'none', watershed_method: str = 'none', smoothing_filter_size: float | None = None, maxima_suppression_size: float | None = None, low_resolution_maxima: bool = False) → SegmentationResult[source]#

Segment one 2D grayscale image into labeled primary objects.

rescale (default True) matches CellProfiler’s own default image loading: integer-dtype images (uint8/uint16/uint32) are divided by their dtype’s max value before thresholding, exactly like CellProfiler’s Image(..., convert=True); float-dtype images are never rescaled (also matching CellProfiler). Set rescale=False to operate on raw pixel values directly instead (matching this project’s measurement API’s own convert=False convention).

threshold is "otsu" (two-class, global, 256-bin histogram – CellProfiler’s default algorithm for any already-float pixel data, which is what every image becomes after rescaling), "otsu_integer" (exact one-bin-per-value histogram; only valid with rescale=False on an integer-dtype image – matches CellProfiler’s Otsu only if CellProfiler would also have skipped rescaling), "otsu_three_class" (a 128-bin, 3-class histogram split; assign_middle_to_foreground picks the lower split, i.e. the middle class counts as foreground, when True (default), or the upper split when False, matching CellProfiler’s "Foreground"/"Background" setting), "li" (Li’s iterative Minimum Cross-Entropy threshold, matching skimage.filters.threshold_li with CellProfiler’s own tolerance formula), "robust_background" (a trimmed mean/median/mode – robust_background_averaging_method – plus a multiple – robust_background_number_of_deviations – of the standard deviation or MAD – robust_background_variance_method – computed after discarding robust_background_lower_outlier_fraction/ robust_background_upper_outlier_fraction of the lowest/highest pixels; matches Threshold.get_threshold_robust_background exactly, including its quirk where a zero lower-fraction also disables the upper trim), "sauvola" (a local mean/standard- deviation formula over a sliding window, only valid with threshold_scope="adaptive" – matches skimage.filters.threshold_sauvola; CellProfiler’s own global_operation Choice does not even include Sauvola, so this raises if combined with threshold_scope="global"), or a numeric manual threshold value, interpreted in the same units as the (possibly rescaled) pixels actually compared against it.

threshold_scope (default "global") matches Threshold.threshold_scope: "global" applies one scalar threshold to the whole image; "adaptive" instead computes a per-pixel threshold map by splitting the image into adaptive_window_size-sized blocks (computing a block threshold with the same algorithm named by threshold – or a direct sliding-window Sauvola computation, which has no block/spline step), blending the block grid across the image with a tensor-product B-spline (matching scipy.interpolate.RectBivariateSpline), and finally clamping the result to [0.7, 1.5] * guide_threshold (the ordinary global threshold, used only as a bound; for "sauvola" this guide is computed via "li", matching CellProfiler’s own shared branch). threshold_map (a same-shape array) and guide_threshold on the returned SegmentationResult are None unless threshold_scope="adaptive"; "manual" and "otsu_integer" are not supported with adaptive scope (CellProfiler’s own local_operation Choice does not include either).

log_transform (default False) matches CellProfiler’s Threshold.log_transform setting, meaningful only when threshold is "otsu", "otsu_three_class", or "li" (CellProfiler itself only exposes this setting for those global operations; it is silently ignored for "otsu_integer", "robust_background", and numeric manual thresholds, matching CellProfiler’s own behavior). When enabled, the threshold is computed on a log-transformed, [0, 1]-rescaled copy of the entire image (not just the masked subset) and mapped back before threshold_correction_factor/clamping, exactly matching centrosome.threshold.log_transform/inverse_log_transform.

exclude_size/min_diameter/max_diameter match CellProfiler’s IdentifyPrimaryObjects size filter: objects whose pixel area falls outside pi * diameter^2 / 4 for the given diameter bounds are removed.

exclude_border_objects (IdentifyPrimaryObjects.exclude_border_objects) removes any object touching the image border (or, if mask is given and nothing touches the image border directly, any object touching the mask’s own border instead).

maximum_object_count (IdentifyPrimaryObjects.maximum_object_count, only enforced when not None) erases every object if the final count exceeds this value, matching CellProfiler’s LIMIT_ERASE.

fill_holes (IdentifyPrimaryObjects.fill_holes) is one of "never" (default), "after_declump_only" (fills background holes enclosed by a single object, after border/size filtering), or "after_thresholding_and_declump" (also fills holes in the binary foreground mask before labeling, limited to area < max_diameter^2). A background region bordered by two or more different objects (not fully enclosed by one) is left unfilled, matching centrosome.cpmorphology.fill_labeled_holes exactly, including its handling of a small object fully nested inside a larger one (absorbed into the enclosing label) and multi-level nested holes.

threshold_smoothing_scale (Threshold.threshold_smoothing_scale, default 0.0 – no smoothing) blurs the image used for the foreground/background comparison (not the value used to compute the threshold, which is always the unsmoothed image) with a Gaussian of sigma = threshold_smoothing_scale / 0.6744 / 2.0, matching CellProfiler’s apply_threshold exactly, including its mask-bleed-over correction near the image border.

unclump_method/watershed_method (IdentifyPrimaryObjects.unclump_method/watershed_method) separate touching objects after initial labeling and before border/size filtering – matching separate_neighboring_objects’s exact position in CellProfiler’s pipeline. unclump_method is "none" (default; no separation), "intensity" (find local intensity maxima in a Gaussian-smoothed copy of the image), or "shape" (find local maxima of the Euclidean distance transform of the foreground, jittered with CellProfiler’s own fixed-seed(0) legacy-RNG noise to break exact ties). watershed_method is "none" (default), "intensity" (watershed on 1 - image), "shape" (watershed on the negated distance transform – reuses the same jittered transform computed above when unclump_method="shape" too, matching CellProfiler’s own if distance_transformed_image is None check), or "propagate" (centrosome.propagate.propagate, a distinct non-watershed algorithm; ignores both image and distance-transform inputs, geometric distance only). Both must be set to something other than "none" for separation to actually run, matching CellProfiler’s own UN_NONE/WA_NONE no-op check.

smoothing_filter_size/maxima_suppression_size override CellProfiler’s own automatic formulas (2.35 * min_diameter / 3.5 and min_diameter / 1.5 respectively) when given explicitly, matching automatic_smoothing/automatic_suppression set to False with an explicit Float Setting value. low_resolution_maxima (IdentifyPrimaryObjects.low_res_maxima) only takes effect when min_diameter > 10.0 (CellProfiler’s own gate); when both are true, maxima are found on a downsampled copy of the image for speed – not yet implemented, raises if triggered.

Grow a secondary object (e.g. "Cells") around each primary object (e.g. "Nuclei"), matching CellProfiler 4.2.8’s IdentifySecondaryObjects module.

image is the secondary stain image (e.g. a cell-membrane or whole-cell marker); primary_labels is the final, kept primary object set (e.g. SegmentationResult.labels from identify_primary_objects()) – a grown secondary object is kept only if its seed primary object survived there.

Ignored entirely for method="distance_n".

fill_holes uses CellProfiler’s labeled-hole graph, but changes only background pixels. Existing nested foreground labels survive. small_removed_labels retains the grown labels before filtering, in the original seed numbering, for downstream neighbor measurements.

cp_anywhere.cppipe#

Importing real CellProfiler .cppipe pipeline files (cp_anywhere.load_pipeline()) – see CellProfiler pipeline import for the declared scope and every explicit gap.

Import real CellProfiler .cppipe pipeline files, translating the settings of every module cp_anywhere implements (IdentifyPrimaryObjects, MeasureImageIntensity, MeasureObjectIntensity, MeasureObjectNeighbors) into this project’s own configuration – not a full pipeline execution engine.

The .cppipe text format (header lines, then one block per module: ModuleName:[attr:'val'|...] followed by indented, strictly positional Label:Value setting lines – the label text is decorative and discarded, exactly as real CellProfiler’s own loader discards it) was reverse-engineered from the real serializer (cellprofiler_core.pipeline.io._v5.dump, the pinned 4.2.8 source), not guessed: every field order, separator, and value encoding below was confirmed by generating real pipeline files with the pinned CellProfiler oracle and reading their literal text. See spec/cppipe-compatibility.md for the full settings-mapping table and every explicit gap.

This module has no CellProfiler dependency – replicating that would require re-implementing CellProfiler’s own per-module upgrade_settings version-migration chains (years of legacy-format branches per module), which is explicitly out of scope. Instead, this importer accepts only the current variable_revision_number for each supported module (the one the pinned 4.2.8 oracle itself writes) and raises a clear, explicit error naming the unsupported revision otherwise – asking the user to re-open and re-save the pipeline in a current CellProfiler first, rather than silently mis-translating an older settings layout.

Pipeline input/organization modules (Images, Metadata, NamesAndTypes, Groups, and anything else this module does not explicitly translate) are recognized and skipped, not silently dropped: see Pipeline.skipped_modules. This importer does not replicate CellProfiler’s own file-matching/grouping logic; the caller supplies already-loaded image arrays by the same names the pipeline’s IdentifyPrimaryObjects/Measure* modules reference.
