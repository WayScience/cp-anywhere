# MeasureImageQuality numerical oracle

`oracle.tsv` is generated by `scripts/reference/generate_image_quality.py`
using the unmodified CellProfiler 4.2.8 checkout at
`2df090ff281cff80943fe679a1c3192fbda9cd6d` and the packages in
`reference/requirements.lock`. The input arrays are synthetic and are
reconstructed by the Rust test. No external pipeline or pixels are vendored.

The `pedcp90` and `pedcp90_band` rows use the 20-pixel blur scale and saturation
options from the CC0-licensed WayScience/pedcp90 pipeline,
`2.feature_extraction/analysis.cppipe` at `3c185d3b0fa4879bd55413d8682cbea4dfdbdff9`.
The second row has a negative slope within that pipeline's DNA acceptance
interval. The generator selects one image explicitly to test the numerical
kernel without invoking loader or pipeline dispatch.

For a full-resolution check, replay the original DNA planes from CPJUMP1
(`cpg0000-jump-pilot`, CC0; plate `BR00118045`, well `A01`, sites 1 and 2).
`scripts/validation/jump_reference.md` describes the source and CellProfiler
image decoding. With the PedCP90 settings, native Rust and WASM differed from
the pinned CellProfiler slope by `9.60e-9` and `1.23e-8`, respectively by site.
These are CPJUMP1 images, not PedCP90 images.

The slope comparison allows `2e-6 + 2e-6 × abs(reference)`. Other metrics keep
their tighter tolerance. On the `pedcp90` row, the reference slope is
`0.9192250404751583`; Rust and WASM both produce `0.9192251621315327`.
Changing only the reference FFT to double precision and rounding the complex
coefficients back to single precision gives `0.9192251571492568`. The Rust
FFT is not a bit-for-bit port of SciPy's PocketFFT.

When the fitted bands contain only FFT roundoff, the logarithm can amplify
small absolute spectral differences into a large slope difference. For example,
a float32 64 × 96 plane with pixel value `(column % 3) / 8` exposes this
limitation. The comparison tolerance does not cover such cases.
