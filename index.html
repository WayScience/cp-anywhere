cp-anywhere#

CellProfiler-compatible measurements for native Python and web browsers

Usage#

The simplest way to call cp-anywhere is measure_files, which accepts TIFF/OME-TIFF, PNG, or saved NumPy array file paths directly (or already-loaded arrays) and returns a tidy pandas.DataFrame:

import cp_anywhere

frame = cp_anywhere.measure_files(
    images={"DNA": "dna.tif", "Actin": "actin.tif"},
    objects={"Cells": "cells.tif", "Nuclei": "nuclei.tif"},
)

A single image/object-set pair can skip the dict form entirely:

frame = cp_anywhere.measure_files("dna.tif", "cells.tif")

The same file formats work from the command line:

cp-anywhere \
  --image DNA=dna.tif --image Actin=actin.tif \
  --objects Cells=cells.tif --objects Nuclei=nuclei.tif \
  --output result.json

--output also accepts .csv or .arrow (Arrow IPC/Feather, covering every feature value as one long-form table, with NaN/Infinity kept as real floats instead of JSON’s string markers). measure_files’s DataFrame can be written the same way with frame.to_feather("result.arrow").

For arrays already in memory, cp_anywhere.measure(...) is the lower-level entry point that returns a MeasurementResult instead of a DataFrame; it has matching to_json/to_csv/to_arrow methods (see docs/src/python-api.md).

Segmentation#

cp_anywhere.identify_primary_objects(...) segments a 2D grayscale image into labeled objects (CellProfiler’s IdentifyPrimaryObjects, Global Otsu or a manual threshold – see spec/segmentation-modules.md for the exact scope), and its output chains directly into measure:

seg = cp_anywhere.identify_primary_objects(dna_image, threshold="otsu")
result = cp_anywhere.measure({"DNA": dna_image}, {"Cells": seg.labels})

Verified against real CellProfiler 4.2.8, exact label-for-label, on both synthetic and real microscopy fixtures: tests/segmentation/, fixtures/segmentation/. Performance: docs/segmentation-performance.md.

Working with the Rust bindings#

This project includes a native extension written in Rust. The performance-critical work lives in a Cargo workspace under crates/:

  • crates/cp_anywhere_core — a plain Rust library with the core routines (unit-tested with cargo test)

  • crates/cp_anywhere_python — a thin PyO3 layer that exposes them to Python as the native module cp_anywhere._native

The Python package under src/cp_anywhere/ calls into the compiled extension, so build it into your environment before running the Python code:

# build the native extension into the active uv environment
uv run maturin develop

# or use the provided poe task
uv run poe develop

uv run poe test rebuilds the extension and runs the Python tests; uv run poe pipeline runs the Rust tests, rebuilds, lints, and runs the Python tests. See the versioning notes for how release versions flow from git tags into the built wheel.
